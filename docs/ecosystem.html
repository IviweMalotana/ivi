05 · Agents · Claude Code

The expensive model plans. The mid-tier builds. The cheap one runs the loop.

Every ticket gets a small tree of agents attached to it — each is a Claude Code subagent with a scoped tool set. The routing is deliberate: the model on each rung is chosen for that rung's job, so you never spend Opus tokens where Haiku would answer, and never a Haiku answer where the stakes need Opus.

  • Opus 4.7 — plans the work, writes tests, does the adversarial review. Slow, careful, expensive.
  • Sonnet 5.5 — builds the slice, writes the release note, mid-loop code changes.
  • Haiku 4.5 — runs the test battery, watches CI, applies the tiny fixes it can be certain of.

Every agent posts back to Jira. Every decision is a comment on the ticket, so a human can read the whole trail without opening a terminal.

08 · Release notes

The release note is the requirements, in past tense.

Written from the ticket's requirements diff, not the commit messages — because "what did the software start doing" is a different question to "what code changed". A behavior change deserves a plain-English line, and a fix deserves the ticket it closes.

Release v0.42.0 Shipped Wed 09:14 SAST PR #418 → main

Cite every generated line back to a source.

Story Founder-flagged Trust

What changed for your users

The generated proposal will now show a citation on hover for every sentence. If the model can't source a sentence with high enough confidence, it doesn't hide it from you — it moves it to a "for review" tray with the reason (no source · low confidence · disallowed claim), and you can accept, reject or rewrite it in one click. A proposal with an un-cited sentence cannot leave the firm.

09 · Weekly cadence

One page a week. Written, not verbal.

The delivery cadence I run on every long-term engagement: a written status every Friday. What shipped, what's next, what's blocked, plus a running decision log so you can trust me to make trade-offs without micromanaging.

What you'll get from me every week

  • Shipped — tickets closed, with a one-line release note each.
  • Next — what I'm picking up on Monday and why it's next.
  • Blocked — anything I need from you, framed as a yes/no.
  • Decisions — trade-offs I made this week, so nothing is a surprise later.
  • Numbers — one graph of the metric you actually care about.

If a week is quiet, the status is short. If a week is loud, it is one page still — not five. Reading it is not homework.
