A4What is "done" for a ticket?

All four gates pass: (1) you signed the Gherkin, (2) Playwright + unit + regression green, (3) adversarial review from a different model to the builder, (4) you verified on staging. Anything less stays open.

B

Scoping & control

How a rough idea becomes signed work.

B1How do you take an idea from me?

Whatever format you use: voice note, Slack thread, whiteboard photo, one-line email. The intake agent transcribes and OCRs it, extracts what/why/open-questions into a scratch doc, then the ticket-writer agent drafts a Jira story from it.

B2What do you need me to sign?

One Jira ticket per unit of work, with a .feature file attached (Cucumber, BDD, Gherkin). One Scenario per requirement, tagged @req-N. You read four to six bullets and reply "signed off" or edit them. Two to five minutes.

B3What happens if I change my mind mid-build?

Cheap before the Gherkin is signed. Expensive after. If a change lands after sign-off, I re-open the ticket, we amend the scenarios together, I re-quote the points. Nothing is silently absorbed.

B4Who decides what goes next?

You do. I recommend an order every Friday with reasoning. You can always overrule; the Jira backlog is the source of truth and the "Next" line in the Friday status is my recommendation, not a decision.

C

Trust & visibility

How you track me without meetings.

C1How do I know you're on track without asking?

Three surfaces, always current. The Jira board (live). The staging URL (updated on every PR). The Friday status (in writing, one page). If you want zero meetings that is fine; the trail is the record.

C2How do you handle bad news?

The moment I know. Not on Friday. If a REQ turns out to be impossible or a deadline is going to slip, you get a Slack message and a proposed re-plan the same day, framed as a yes/no.

C3How do I know an AI output is trustworthy?

Every generated line cites its source; anything below a confidence threshold is quarantined to a review tray with the reason. This is the pattern I built at Emerald Path (UK accountancy AI gateway, 20 rounds of QA, citations grounded).

C4Do you write tests?

Yes, three suites, all keyed to a REQ so a red test names the requirement that failed.

  • 1. Cucumber + Playwright for the user flows.
  • 2. Vitest for the small invariants.
  • 3. Regression pull from last quarter's bugs.

A test is never disabled to "make it pass". A flake is investigated as if it were real, once.

D

Agents & models

Who does what, on which model, and why.

D1How many agents run on a ticket?

Eight. Each is a Claude Code subagent with a scoped tool set. Model ids are fixed in the subagent front-matter, so the cheap one cannot silently escalate to the expensive one.

release-writersonnet 5.5
Drafts release note from the scenarios diff.
D2Why per-agent model routing?

Opus for planning, tests, review. Sonnet for build and release notes. Haiku for the loop and small fixes. You never spend Opus tokens where Haiku would answer, and you never get a Haiku answer where the stakes need Opus.

D3Who reviews the code the AI writes?

A different model to the one that wrote it. The builder is Sonnet 5.5; the reviewer is Opus 4.7. Different training, different blind spots. The reviewer blocks merge on any finding with a real failure scenario.

E

Continuity & ownership

What happens when I'm not there.

E1What if you disappear tomorrow?

Three things survive without me. (1) The agents live in your/repo/.claude/agents/*.md. Another Claude Code operator can pick them up. (2) The .feature files are the spec, in your repo. (3) Jira has the full trail: every requirement, every decision, every review comment.

E2Who owns the code and the agents?

You. All IP is yours from day one, in your repo, under your license. I do not retain any part of it. The subagent files are plain markdown; you can read and modify them without me.

E3Can your agents run without you?

Yes. They are triggered by Jira status changes and GitHub events. Once wired, an intern or your own senior dev can move a ticket through the pipeline. My job over time is to make myself less necessary, not more.
